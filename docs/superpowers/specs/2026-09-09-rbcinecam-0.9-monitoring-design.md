# RB CineCam 0.9 Alpha Monitoring Design

## Goal
Evolve RB CineCam 0.8 into a production-monitoring build with always-visible real audio metering, real image scopes, reliable camera/gallery/player navigation, and a clearer production HUD without breaking the existing capture engine.

## Approved behavior
- Keep current landscape camera layout and working video/photo/focus/manual controls.
- Audio meter must always occupy a visible monitor area. If microphone metering is unavailable, show AUDIO N/D instead of fake movement.
- Add SCOPES control with OFF, RGB histogram and luma waveform. Scopes are computed from live camera analysis frames and are never burned into recordings.
- Gallery header must have explicit white back-to-camera navigation. Player must have separate return-to-gallery and return-to-camera actions.
- Gallery rows must show useful video metadata and clear play action.
- HUD must surface recording state, free storage, battery, audio state, active capture format and actionable errors.
- Preserve internal player, grids, shutter-angle behavior and stable alpha update signing.

## Architecture
Use CameraX ImageAnalysis as a parallel non-recorded analysis use case bound with Preview, VideoCapture and ImageCapture. A ScopeAnalyzer samples YUV_420 frames to derive RGB histograms and luma waveform columns on a background executor, then exposes immutable ScopeFrame data to Compose. Audio remains based on real PCM capture through AudioLevelMonitor and is displayed in a fixed monitor strip rather than a small overlay that can disappear behind the preview layout.

Media navigation remains state-driven inside CameraScreen: CAMERA -> GALLERY -> PLAYER, with explicit transitions in both directions. Media metadata comes from MediaStore columns already associated with RB CineCam files.

## Non-goals for 0.9
- No fake waveform, histogram, zebra, peaking or RGB parade.
- No LOG/RAW pipeline in this release.
- No LUT processing in this release.
- No destructive changes to existing recorded media format.

## Validation criteria
1. Unit tests for scope math and metadata formatting pass.
2. Android debug build passes in GitHub Actions.
3. Audio panel is always rendered, either with real dBFS values or AUDIO N/D.
4. RGB histogram changes with incoming ImageAnalysis frames.
5. Luma waveform changes with incoming ImageAnalysis frames.
6. Gallery back button is explicitly visible and returns to camera.
7. Player has visible actions for gallery and camera.
8. Recording/photo/gallery/manual controls still compile and remain wired.
